「書くな」では防げない。
実行場所を分ける。

reviewer が coverage/ を作ったため、Ralph は本体の変化を検知して正しく fail-close しました。根本原因は、書き込み可能な reviewer を承認対象と同じワークツリーで動かしていたことです。

いま起きていること

承認待ちの本体staged snapshot
→
reviewer が同居coverage/ を生成
→
Ralph 停止本体が変化した
修正: reviewer を使い捨て worktree に隔離する。
さらに静的レビューだけを指示し、本体の fail-close は残す。

直した後

tree を固定承認対象を1つの ID に
→
別 worktreereviewer の副産物を隔離
→
完全一致で commit固定した tree だけ

runner の新しい流れ

1
承認対象を固定git write-tree で worker と pre-commit hook の成果を1個の tree ID にする。
2
使い捨て worktree を作る固定した tree を detached worktree に展開。本体とは別の作業場所にする。
3
reviewer は静的レビュー固定 diff だけを読み、test・build・lint・coverage・package manager は実行しない。
4
隔離先を必ず破棄成功、却下、Codex エラーのどの経路でも worktree を削除する。削除失敗も安全停止する。
5
本体を再確認して commitHEAD、staged tree、tracked、untracked を確認し、固定した tree だけを commit する。

採らない案

× coverage/ を単に無視する: 別の生成物で再発し、reviewer の意図しない編集も見逃します。

× review 後に自動削除する: 本物の変更を「生成物」と誤認して消す危険があります。

× 変更検知を止める: 承認した tree と commit する tree の一致保証が壊れます。

✓ 使い捨て worktree: reviewer が指示に反して生成物を作っても、本体に混ざらず隔離先と一緒に消えます。

✓ 本体側の変更検知を維持: reviewer が絶対パスなどで隔離を抜けた場合は、変更種別とパスを表示して停止します。

必要な回帰テスト

reviewer prompt が test・build・lint・coverage・package manager を禁止すること。reviewer が隔離先に coverage/ を作っても本体が clean なこと。隔離を抜けた変更はパス付きで拒否すること。reviewer 異常終了時も worktree が残らないこと。

境界: この隔離は、test や coverage が偶発的に作る作業ファイルを本体から分けるものです。reviewer を悪意あるプロセスとして Git の共有 object database から隔離するものではありません。互換性については古い同居レビュー経路を残さず、git clean、untracked 無視、生成物ごとの例外追加といったフォールバックも追加しません。
